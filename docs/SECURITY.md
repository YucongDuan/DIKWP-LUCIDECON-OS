# Security and privacy boundary

The reference tool is local and has no network, credential, model, browser-control or payment connectors. Run it as an ordinary OS user in a dedicated private directory. Do not use it for hiring, credit, eligibility, diagnosis or other automated decisions about third parties.

Inputs are untrusted declarations. Reviewer names, references and route authorization booleans are not cryptographic proof of authority. The evidence gate is a completeness and consistency check, not a verification service. A reviewer must separately examine the original documents.

The CLI limits JSON input size and validates core numeric/date/enum fields. It refuses existing nonempty result directories. Hash-chain appends use a local exclusive lock file and fsync. A crashed process may leave a lock requiring manual review. File-level output and event appends are not a distributed transaction; do not use this as a concurrent multi-tenant financial service.

A chain can be entirely regenerated by someone controlling the file system. An independently held checkpoint detects changes relative to that checkpoint, but does not authenticate the actor or the substantive claim. Full replay tests computation, not the world.

Personal files are not encrypted and no retention service is present. Delete/export them deliberately under an appropriate local policy; immutable-record design does not override privacy duties. Browser previews stay in memory unless exported; extensions, shared devices, browser downloads and screenshots remain outside this boundary.

Public deployment, credential authentication, encryption, access control, monitoring, independent security review and jurisdiction-specific legal/financial review are future integration requirements. There is no production security certification.
